# Report Spec - Google Play market analysis (Power BI)

## Report identity
- Report name: GooglePlay (powerbi/GooglePlay.pbip)
- Semantic model: GooglePlay.SemanticModel (local, new; Import from CSV tables written by the Python pipeline)
- Audience: hiring managers / analytics leads reviewing a DA portfolio; secondarily a small studio's lead choosing the next title
- Primary purpose: recommend where a small studio should build next (category and game genre), then show the market map, the drivers of a hit and the player-sentiment context behind it
- Delivery target: local PBIP only, committed to the repo, with page screenshots in the README (no Fabric publish)

## Semantic model binding
- Entry mode: Local Model (created in this build; the repo has no model yet)
- Model name: GooglePlay
- connectionString: byPath ../GooglePlay.SemanticModel
- Data source: M parameter `CsvFolder` = `D:\Vi\DA_Game\google-play-market-analysis\powerbi\data\`

## User decisions and constraints
- Scope: the findings already published in README.md / results/; no new analysis
- Page count: 5
- Interactivity: page navigator top right on every page; on the Drivers page a tile slicer "All apps / Games only" (fact_apps[app_scope]) and a searchable category dropdown, both in the top-right filter region; hit-rate measures recompute live from fact_apps
- Design direction: same editorial identity as the Flood-It and Cookie Cats reports
- Publishing: none
- Tooling: Python exports CSVs; TMDL model written directly; PBIR generated by a Node script (Flood-It pattern); powerbi-report-author CLI validate; Power BI Desktop preview + screenshots
- Model edit permissions: new model; every number on a page comes from a measure or a column; no hard-coded numbers in DAX
- Accessibility: WCAG AA contrast, alt text on every chart, highlight (Game) never colour-only (bold label + title text)
- Data caveats: 2018 snapshot; scrape over-represents popular apps; installs are bucket lower bounds; no revenue; drivers are correlational

## Narrative
- Core story: games are a strong market but 45% of them hide under FAMILY; among game genres, Racing, Role Playing and Strategy combine a high hit rate with the least concentrated installs; once there, be free, keep updating, and staff support because game players complain the most.
- Audience promise: every page opens with a one-line takeaway; every chart has its definition as subtitle and an insight with a source line.
- Key questions answered: What should we build? Which app categories are open? Which game genres are open? What separates hits? What do players complain about, and what can't this data tell us?

## Design identity
- Tone: Editorial analyst briefing (same as Flood-It)
- Signature: takeaway headline + definition subtitles + accent-barred insight card ending in a grey `Source:` line; on the two market maps, the recommended segment is the only orange dot

## Page plan
1. Overview - Executive Summary (variant A: KPI strip + chart + recommendation panel). Six KPI cards; games by genre split GAME vs FAMILY (stacked bar, the data catch); recommendation panel.
2. App categories - Analytical Canvas (variant B: map left, ranking right). Scatter hit rate vs top-10% install share (size = apps); top-10 ranking table; insight.
3. Game genres - Analytical Canvas (variant B). Same scatter for game genres; full genre table; insight.
4. What makes a hit - Comparative Benchmark (variant B: three columns). Hit rate by rating band, by update recency, free vs paid; scope + category slicers; one insight band.
5. Player sentiment and limitations - Narrative Story (variant A: two columns). Negative-review share by category (bar, Game highlighted); limitations text.

## Design system summary
- Theme: `PortfolioEditorial` (copy of Flood-It) - background #FCFCFB, text #0B0B0B, secondary #52514E, dataColors [#2A78D6, #EB6834, #1BAF7A], Segoe UI
- Colour semantics: blue #2A78D6 = default for every segment/measure; orange #EB6834 = the segment the page recommends or highlights (Game category, recommended genres, GAME-filed games vs FAMILY-filed in blue on page 1); never a third meaning
- Typography: Segoe UI Semibold 28 / Semibold 14 / 11 / 12 / 10 grey, as Flood-It
- Layout: 1920 x 1080, 12 x 12 grid, margin 32, gutter 24, snap 8; header row reserved
- Accessibility: AA contrast; alt text = chart title + insight; tooltips on every chart (segment, apps, hit rate with Wilson CI)

## Model requirements
- Tables (CSV in powerbi/data, written by a new `python -m gplay.powerbi_export` step from the same objects as metrics.json):
  - `fact_apps` - 9,659 rows: app, category, category_label, primary_genre, is_game (0/1), game_filed_under (GAME / FAMILY / blank), app_scope ("All apps" kept as a separate flag: is_game drives "Games only"), rating, reviews, installs, is_hit (0/1), price, is_paid, pricing ("Free"/"Paid"), size_mb, rating_band + rating_band_order (apps with 100+ reviews; blank otherwise), update_age + update_age_order
  - `fact_category_scores` - 33 rows from results/category_scores.csv + category_label + opportunity_rank + is_highlight
  - `fact_genre_scores` - 13 rows from results/game_genre_scores.csv + opportunity_rank + is_recommended (top 3)
  - `fact_category_sentiment` - 20 rows: category_label, apps, neg_share, is_game
  - `kpi_metrics` - scalars (snapshot date, labelled reviews, spearman rating/installs, sentiment validation rho)
- Measures (`_Measures`): Apps; Games; Games Filed Under Family; Games Filed Under Family %; Hit Rate (DIVIDE(SUM is_hit, COUNTROWS), live); Hit Rate Games; Free Hit Rate; Paid Hit Rate; Median Rating; Negative Review Share
- Relationships: none needed (each visual reads one table; the Drivers slicers filter fact_apps only)
- Sort: rating_band by rating_band_order, update_age by update_age_order, ranking tables by opportunity_rank
- Reconciliation: DAX query checks Hit Rate by category / free / paid / rating band / update age against results/metrics.json (tolerance 1e-6)
